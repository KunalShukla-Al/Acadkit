## Owner isolation inventory (18 Nov)

From a local database built from every migration through 064:

- All 28 tables in `public` have row-level security, and every policy names `owns_device` or `auth.uid()`.
- Signed out (anon), no table policy and no `public` function applies.
- Signed in, the only callable functions are the three `match_*` searches, all `security invoker`, so
  `study_chunks` and `lecture_moments` policies still filter them.
- `sent_notifications` has no policy: only the service role touches it.
- `owns_device` lives in `private` (migration 049) and isn't served over HTTP.

`supabase/tests/database/rls.test.sql` now fails if any of the first four stops being true.
